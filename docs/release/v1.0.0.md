## DSigMatcher Native 1.0.0

The first release of DSigMatcher as a native port of Diaphora's binary diff. `dsigmatcher diff`
produces the same `.diaphora` results file as Diaphora 3.4.2, row for row, from a single
executable with no Python, and `port` / `update` carry function names from one build to the next.

### Highlights

- **Diaphora parity.** The diff engine is a C++20 port of every stage of Diaphora 3.4.2's diff:
  the pre-loop passes, all 50 SQL heuristics (Diaphora's own SQL, run through SQLite), callee
  diffing, related constants, related compilation units, local affinity and the final multimatch
  pass. On all 7 finished reference pairs its output is identical to Diaphora's: same rows, same
  order, same line numbers, same ratios.
- **Fast.** On the largest finished pair (userenv, PDB → no PDB) the native diff takes about a
  minute; Diaphora takes hours. Diaphora's slowest pass, "Related compilation unit", took 24.4 s
  natively against 2 h 23 min in Python on that pair's first iteration.
- **Label once, carry forward.** `port` applies match results (from `dsigmatcher diff`, from
  Diaphora itself, or from a diff it runs on its own) to the next build's export and writes a labelled copy that is itself a
  valid export. Every hop is recorded in `dsig_provenance`, and every ported name in
  `dsig_name_origin` with its original name, hop count and cumulative confidence. Real names
  already in the target are never replaced unless you ask.
- **Exports without the IDA GUI.** `extract` (from an `.i64`/`.idb`, which is never modified)
  and `ingest` (from a raw binary, offline, with or without a matching PDB) run IDA's idalib and
  Diaphora's unmodified exporter. `update` ingests, diffs and ports a new build in one command.
- **Self-contained binaries.** SQLite 3.51.1 (the version the reference results were produced
  with) and the C/C++ runtime are linked in. The Linux binary is fully static.

### Parity evidence

Each pair is two real Diaphora exports of real binaries, diffed by unmodified Diaphora
3.4.2-4-g621ec26 in its default configuration and by `dsigmatcher diff`, then compared field by
field (`tools/parity/run_parity.py`). "Identical" means L2: the same `results` and `unmatched`
rows, in the same stored order, with the same `line` numbers, ratios, categories and
descriptions.

| Pair | Diaphora mode | Rows | Result | Native time |
|---|---|---:|---|---:|
| ls-old → ls (Diaphora's test samples) | normal | 278 | identical | 2.2 s |
| ls → ls-old | normal | 286 | identical | 1.6 s |
| userenv 9168 (PDB) → 9278 (no PDB) | normal | 2180 | identical | 63 s |
| userenv 9168 (PDB) → 9278 (PDB) | patch diff | 643 | identical | 0.13 s |
| win32u 9168 (hand-labelled `.i64`) → 9444 (no PDB) | stripped binary | 1510 | identical | 0.15 s |
| cryptbase 1 (PDB) → 8875 (no PDB) | normal | 29 | identical | 0.2 s |
| cryptbase 8875 (PDB) → 9444 (no PDB) | stripped binary | 43 | identical | 0.03 s |

Measured on Windows x64 with the bundled SQLite 3.51.1. Ported and scored against the PDB names
of each target build, native and Diaphora results give identical scores on every pair.

Also verified along the way:

- The ratio engine is bit-identical to Diaphora on 167,902 function pairs from the reference
  exports.
- The C++ port of CPython's `difflib` gives the same output as Python on 5,377 diffs from the
  reference results and 12,000 random cases.
- Every stage was checked on its own against snapshots of Diaphora's internal match state.
- `extract` of a hand-labelled win32u `.i64`, `ingest` of win32u without a PDB and `ingest` of
  cryptbase with its PDB produce exports identical, table by table, to the reference exports.

An eighth pair (sechost, PDB → no PDB) was still running in Diaphora, which needs about a day for
it, when this release was prepared. The native diff of the same pair completes in about 7 minutes.

### Requirements

- `diff`, `port`, `info` and `version`: just the binary.
- `extract`, `ingest` and `update`: IDA Pro 9.x with
  idalib and the Hex-Rays decompiler, a Python that can import `idapro`, and a Diaphora checkout
  (3.4.2-4-g621ec26 recommended; not bundled). Point to them with `--ida-dir`, `--python` and
  `--diaphora-dir`, or `DSIG_IDADIR`, `DSIG_PYTHON` and `DSIG_DIAPHORA_DIR`.

### Known limitations

- Only Diaphora's default configuration is supported. Its unreliable heuristics, relaxed ratios,
  machine-learning model and project scripts are refused with exit code 4.
- Diaphora's "Same constants related matches" pass iterates a Python set, whose order changes
  between Python processes; DSigMatcher uses one fixed order. On every reference pair the effect
  was erased by the next cleanup and the final results were identical.
- The full reference pairs were run on Windows x64. Linux and macOS use the same bundled SQLite and
  pass the same test suites in CI, but the full pairs have not been rerun there.
- `extract` and `ingest` need IDA; there is no native exporter yet.
- In Diaphora's "stripped binary" mode, functions are paired by address, and those pairs are
  often wrong when functions moved between builds. `port` never lets them replace a real name
  unless both `--overwrite-existing` and `--overwrite-stripped` are given; review such results
  before porting them into an unnamed target. Multimatch rows are not ported unless
  `--include-multimatch` is given.
- The macOS build requires macOS 26.0 or later.
